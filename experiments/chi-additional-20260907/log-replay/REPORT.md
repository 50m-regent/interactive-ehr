# 追加評価の候補と診断ログの再集計

2026年9月7日。既存データによる追加評価は行う価値がある。今回の再集計では、現在の候補集合が検査方法の違いを十分に区別できないことが分かった。次は、結果を保つSQLの別解と、注釈の値を残して意味を変えるSQLを優先したい。

今回は保存済みログの再集計を実施した。元データを使うSQL変換実験は計画までで、まだ実行していない。計画、コード、結果はローカルに保存し、論文本文、GitHub、Notionには未反映である。

## SQLの一致と注釈の照合が重なっている

正式評価のtest 763組とvalidation 758組について、記録済みの問題コードを使い、検査項目を外した場合の受理・拒否を再構成した。対象はそれぞれ6,104行と6,064行。元の実装は検査ごとの問題を集め、空集合なら受理するため、記録から受理・拒否だけを再計算できる。

| 再構成した条件 | testの不整合流出 | validationの不整合流出 |
|---|---:|---:|
| 層間検査の全項目 | 0/763 | 0/758 |
| SQLの完全一致だけ | 516/763 | 510/758 |
| 成果物内検査とSQLの一致 | 129/763 | 127/758 |
| 成果物内検査とSQL・接続先の一致 | 0/763 | 0/758 |

| 注釈との照合を除く | 0/763 | 0/758 |
| SQLの完全一致と注釈の照合を除く | 238/763 | 237/758 |
| 成果物内検査と注釈の照合 | 129/763 | 127/758 |

妥当候補は、再構成した全条件でtest 763/763、validation 758/758が受理された。いずれも参照情報から作った候補であり、多様な別解への受理率を示す結果ではない。

SQLの完全一致を外すだけでは、注釈の照合が同じ不整合を捉える。逆に注釈の照合を外しても、SQLの完全一致が捉える。したがって、100%検出がSQLの完全一致だけによるとは断定できない。先の査読で挙げた参照情報への依存は残るが、どの照合が拒否を決めているかは、この結果に合わせて区別する必要がある。

成果物内検査にSQLと接続先の一致を加える条件は、層間検査の全項目と受理・拒否が一致した。両分割の妥当・不整合候補を合わせた3,042候補で判定差は0件だった。この候補集合では、それ以外の検査が拒否件数を増やしたとは言えない。一方、診断の内容、問題箇所の特定、実行時間、復元、利用者への分かりやすさが同じという意味ではない。

## 次の実験で区別したいこと

第一に、同じ結果を返す別のSQLを誤って拒否するか調べる。元のSQL、空白だけを変えた対照、問い合わせ全体を包んで `WHERE 1 = 1` を加えた候補を比べる。元と変換後の列・型付き結果の多重集合を、同じデータベース状態で照合する。既存オラクルは正解SQLの一致を要求するので、この実験の正解判定には使わない。

第二に、注釈の患者IDや項目名を残し、比較演算子や条件の結び方を変えた候補を使う。これにより、値の存在を調べる検査と、条件の意味を調べる検査の違いを検討できる。変換後の妥当性をどう判断するかと、結果が変わらないケースの扱いは実行前に固定する。

この二つを組み合わせると、妥当な別解を拒否する検査と、値が残っている誤った問い合わせを受理する検査を区別できる。現在の8種類の候補を増やすだけよりも、査読で残った疑問に対応する評価になると判断する。

正式評価で使ったEHRSQL-2024のcommit `f9e1aa02160d39e3f8df52bf5c69c5cf2e472499`には、testの注釈JSON、データJSON、約37 MBのSQLiteが残っていることをGitHub APIで確認した。ローカルには元データが見当たらないため、同じ版を再取得し、保存済みマニフェストのチェックサムと照合して使う。生成モデルや人対象実験を使わず進められる範囲である。[公開データの固定版](https://github.com/glee4810/ehrsql-2024/tree/f9e1aa02160d39e3f8df52bf5c69c5cf2e472499/data/mimic_iv)

## 採否判断への影響

採択を支持しにくいという判断は変わらない。ただし、現在の検査が何に依存しているかについて、より具体的な説明ができるようになった。保存済みの全結果を使う再集計でも、査読で問うべき比較条件を絞れる。

次のSQL変換実験で良い結果が出ても、実際の生成エラーの分布、臨床シナリオの妥当性、医療者への効果が示されるわけではない。追加の証拠が支持する範囲を明示し、原稿の貢献と対応させる必要がある。
