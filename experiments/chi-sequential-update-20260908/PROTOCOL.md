# 実アプリの連続更新で条件の保持と検査の差を確かめる

2026年9月8日、モデルへの最初の呼出前に固定する探索的な実験計画です。[Issue #54](https://github.com/50m-regent/interactive-ehr/issues/54)と[NotionのCHIタスク](https://www.notion.so/3bbc165ad0ab8124aa53ebf702a83513)で追跡します。先行する20件の単発生成で、簡単な期間検査と結果を実行して比べる検査に差が出なかったため、実アプリの連続更新へ対象を広げます。先行結果を踏まえて設計した追加評価であり、独立した確認研究ではありません。

## 同じ候補に同じ要求条件を渡して比較する

調べるのは、簡単なSQL条件の検査を通る実生成の不適合を、結果と表示の検査で追加検出できるかです。適合する別の書き方を過剰に拒否するかも記録します。複数の合成DB状態で検査すると、一つの状態で見逃した不適合を検出できるかを副次的に調べます。差が出なければ、今回の条件で追加価値が示されなかったと報告します。

モデルが出す同じ最終状態に、次の4条件を適用します。検査の判定は生成処理へ戻さず、候補を選び直したり修復したりしません。

| 条件 | 調べる内容 |
|---|---|
| 構造と実行 | 更新処理の完了、SQL実行、実際のキャッシュとSQL結果の一致、参照先と表示列の存在 |
| 簡単なSQL条件 | 共通の表示条件、必須の患者・項目・期間条件、参照テーブル、列、集約の種類、欠損を除いたCOUNT、単位の乗算とラベル、並び順、件数上限 |
| 1状態の結果と表示 | 共通条件に加え、状態0で得た結果を要求からPythonで計算した期待値と照合 |
| 3状態の結果と表示 | 同じ検査を状態0・1・2で実行 |

簡単なSQL検査はsqlglotの構文木を使います。ANDで必須となる条件を調べ、ORの片枝を必須とは扱いません。期間のBETWEEN、左右を入れ替えた比較、固定日時のdatetime式に対応します。参照SQLの文字列は使いません。追加の条件や任意の算術式の意味は証明しません。この限界は人工的な対照でテストし、実生成で見つかった例とは分けます。一般的なSQL意味解析に対する最強の比較手法とは扱いません。

検査に渡す要求条件はすべて共通です。表示条件は部品のIDと順序、データ接続、表示種別、表の列、グラフの軸です。タイトルの言い換え、表の高さなどは採点しません。表のcolumn_orderが未指定で全列を表示する場合も許容します。結果は列と行順を保って比較し、数値の許容差は相対・絶対とも1e-9です。NULLと0は区別します。

## 6系列で3回ずつ更新する

各系列は、SYN_Aの直近1日間の体重と、変更しない脈拍の表から始めます。measurementsは、この実験のプロセスだけで登録する合成DWHモデルです。患者はSYN_A・SYN_B・SYN_C、項目は体重と脈拍に限ります。実患者情報や実験参加者から得たデータは使いません。

| 系列 | 1回目 | 2回目 | 3回目 |
|---|---|---|---|
| 期間・最新件数・単位 | 直近7日へ変更 | 最新3件へ変更 | kgからgへ変更 |
| 患者・期間・最新件数 | SYN_Bへ変更 | 直近3日へ変更 | 最新1件へ変更 |
| 平均・患者・単位 | 直近7日の平均へ変更 | SYN_Cへ変更 | kgからgへ変更 |
| 件数・期間・患者 | 欠損を除いた件数へ変更 | 直近7日へ変更 | SYN_Bへ変更 |
| グラフ・期間・患者 | 折れ線へ変更 | 直近14日へ変更 | SYN_Cへ変更 |
| 期間・項目・順序 | 直近3日へ変更 | 脈拍へ変更 | 新しい順へ変更 |

件数・課題・順序は、生成前にinputsへ固定します。要求は目的に合わせて作成した合成課題であり、医療者の自然な要求から抽出した標本ではありません。平均はNULLを除外し、該当値がなければNULLです。件数は非NULL値を数え、該当値がなければ0です。集約表示はvalueとunitの2列とします。

各系列で、アプリの完了状態を次の更新へ渡します。意味上の不適合が見つかっても、モデル出力は修正せず、その状態から継続します。採点上の目標は、それまでの要求を累積した状態です。前の不適合が後へ残った場合は、新たな独立した生成誤りとは数えません。系列ごとの最初の不適合と、先行する不適合の有無を別に記録します。

更新処理がfailedになった系列は、その途中状態を保存して後続を実行しません。アプリは失敗前の途中状態も保持する実装ですが、利用者の次の判断を仮定して実験を続けることはしません。未実行の手順は分母から消さず、計画18件に対する未実行として別記します。

## 更新の処理を変えず、外部との接続を記録する

`update_scenario_graph_incrementally`を呼び、既存の更新範囲判定、プロンプト作成、ノード生成、正規化、SQL結果の格納を通します。`GeminiMixin.generate`とPydanticによる応答検証も既存コードを使います。

実験内で差し替えるのは、合成DWHモデルの登録、SQL実行先、SDKクライアントの初期化です。SDK呼出を記録する処理で、モデル設定、回数、入力長、費用の見積もり上限を固定します。並列のSDK呼出は記録処理で直列化します。このため実アプリの応答時間の評価には使いません。既存のプロンプトや更新規則は実験の都合で修正しません。

SQL実行は先行実験と同じ読み取り専用の制限を使います。measurements以外へのアクセス、書込み、外部機能を拒否し、1,000行と約100万VM命令の上限を置きます。合成DBには期間境界、対象外の患者・項目、NULL、空の期間、未来の対照行を含めます。モデルにはDBの行を渡しません。

最初の生成前に、実行コード、検査コード、テスト、計画、依存の版と入力をcommitで固定します。新しい出力ディレクトリだけへ書き込み、各SDK要求、スキーマ、加工前の応答テキスト、メタデータ、全イベント、キャッシュ状態を保存します。既存の正式結果と先行実験の出力は上書きしません。

## 採点と検証の範囲を区別する

採点は別の状態3・4・5・6で、要求から作った参照SQLの実行結果と比較します。検査側はPythonで期待値を計算し、参照SQLを読みません。全18目標について、両実装の値が7状態すべてで一致することをテストしてから生成します。

両実装は同じ明示的な要求条件と表示検査を共有します。合成状態も同じ生成規則に由来します。別の担当者や専門家による独立した正解判断ではなく、一般のSQL同値性の証明でもありません。

主指標は不適合の受理件数と適合の拒否件数です。系列別の最初の不適合、処理失敗、未実行、検査間で判定が異なる更新IDを示します。6系列しかなく、目的抽出でもあるため、母集団の誤り率や有意差は推定しません。18件を独立標本として信頼区間を計算しません。

保存済みのSDK応答を使って同じ更新処理をローカルで再実行し、要求、グラフ、キャッシュ、イベントの一致を確認します。追加のモデル呼出は行いません。判定行からの別集計、チェックサム、実際のStreamlit描画データも確認します。生成状態に表示の警告が出た場合は失敗として隠さず報告します。人の理解や視認性は評価しません。

## 呼出回数と停止条件を固定する

Gemini 2.5 Proを、既存のVertex AI設定で使用します。temperatureは0.2、top_pは1、max_output_tokensは8,192、thinking_budgetは1,024、seedは20260981から呼出ごとに1増やします。seedは再現を保証しません。各API要求のタイムアウトは120秒、SDKのattemptsは1で、自動再試行と修復を行いません。

最大54呼出、1要求120,000 UTF-8バイト、保守的な料金見積もりで5米ドルを上限とします。料金は[Google Cloudの公開料金](https://cloud.google.com/vertex-ai/generative-ai/pricing)を2026年9月8日に確認し、入力100万トークン1.25米ドル、回答と推論100万トークン10米ドルで計算します。入力は要求全体のバイト数に2,000を加え、出力は回答上限と推論枠を合わせた9,216トークンを各呼出前に予約します。これは請求額の確定ではありません。

計算はローカルCPUと既存のVertex AI接続を使い、GPUや新しい有料資源を用意しません。想定時間は10〜25分です。回数・入力長・見積もり上限を越える次の呼出は送信せず、APIエラー時は全体を停止します。通常のSQL・スキーマ・更新失敗では当該系列を停止し、別系列へ進みます。クラッシュは自動再実行しません。

```bash
uv run python scripts/run_sequential_update_pilot.py prepare --inputs experiments/chi-sequential-update-20260908/inputs
uv run python scripts/run_sequential_update_pilot.py generate --inputs experiments/chi-sequential-update-20260908/inputs --output results/evaluation/chi_sequential_update_20260908
uv run python scripts/run_sequential_update_pilot.py score --inputs experiments/chi-sequential-update-20260908/inputs --output results/evaluation/chi_sequential_update_20260908
uv run python scripts/run_sequential_update_pilot.py replay --inputs experiments/chi-sequential-update-20260908/inputs --output /private/tmp/chi-sequential-replay --replay-source results/evaluation/chi_sequential_update_20260908
```

結果と限界は同じディレクトリのREPORT.mdへ記録し、README、GitHub、Notionの次の作業を更新します。採択を支持する判断は、実際に得られた比較結果に基づいて行います。
