## 1. シナリオ（scenario node）

### 1.1 シナリオの名称

例：「2型糖尿病外来 定期再診」

> 麻酔科術前外来
> 

### 1.2 一文で表す診療場面

だれが、いつ、何のために行う診療か。

例：「内分泌内科の定期再診で、HbA1c と処方を中心に経過を評価し、必要に応じて投薬調整を行う」

> 麻酔科医が、手術の前日までに、麻酔をかけるうえで注意すべき患者背景を確認し、患者へリスクの説明を行う。
> 必要に応じて、他科へのコンサルトを行う。

### 1.3 対象患者の典型像

- 年齢層：小児（保護者と受診）～高齢者まで様々
- 主病名 / 併存疾患：手術が必要な病気全般、併存疾患はすべての病気がありうる
- 来院頻度：手術1回につき一度きり
- その他特徴（重症度、ADL 等）：

### 1.4 想定される時間制約

例：診察枠5分、初診20分、急変時の即時判断 など

> 事前にカルテの確認を行う際に制約は無し
> 実際に当日患者説明を行うのは10分程度

## 2. タスク（task nodes）

本シナリオを構成する「個別の認知的作業」を、診察の流れに沿って一覧化。各タスクは「医師がこの瞬間に何を判断 / 確認 / 入力するか」の単位。

### 2.1 タスク一覧（診察フロー順）

| # | タスク名 | 何を判断・確認・入力するか | 通常使う情報源 |
| --- | --- | --- | --- |
| T1 | 患者の基本的な特徴の確認 | 年齢・性別・身長・体重・BMI のチェック | 患者情報ページ |
| T2 | 手術の確認 | 手術対象の病名、術式名、手術時間、手術体位 | 手術申し込み |
| T3 | 生活歴、アレルギーの確認 | 喫煙歴、飲酒歴、アレルギー のチェック、アレルギーあれば記入 | 患者情報ページ |
| T4 | 既往歴と治療内容の確認 | 既往歴のチェック、該当箇所に転記、内服薬や手術歴あれば転記 | 患者情報ページ、過去カルテ |
| T5 | 検査結果の確認 | 血液検査、心電図、胸部レントゲン、呼吸機能検査の結果チェック、異常があれば転記 | 各検査部門ページ |
| T6 | 麻酔歴の確認（手術歴あれば） | 麻酔記録から麻酔に問題がなかったか確認、問題あれば転記 | 麻酔記録システム |
| T7 | 麻酔リスクの判定 | 患者に説明が必要なリスク、麻酔時に注意すべきリスクをリストにまとめ記入 | これまでの情報すべて |

### 2.2 タスク間の依存関係

あるタスクが別タスクの結果に依存する場合、その関係を記述。

例：「T2（処方変更判断）は T1（血糖トレンド確認）の結果に依存する」

> T1,T2は順不同だが最初、T3-T6は順不同、T7が最後
> T6はT4の結果次第

## 3. ウィジェット（widget nodes）

各タスクで「画面上にどう情報が並んでいると判断しやすいか」を記載。ウィジェットは表・グラフ・指標カード・選択肢・入力欄など、UI 上の構成単位。

### 3.1 利用可能なウィジェット種別（提示用カタログ）

- **表示系**：Table（表）、DataFrame、Metric（指標カード）、Markdown / Text（注記）
- **グラフ系**：LineChart（折れ線）、BarChart（棒）
- **入力系**：Selectbox、Multiselect、DateInput、TextInput
- **レイアウト系**：Columns（横並び）、Tabs（タブ）、Expander（折りたたみ）

### 3.2 タスク × ウィジェット 対応表

| タスク# | ウィジェット名 | 種別 | 表示意図・条件・並び順 |
| --- | --- | --- | --- |
| T1 | 患者情報一覧 | Table | 一覧できればよい、ただし測定日時が必要（体重が古いと困る） |
| T2 | 手術申し込み内容一覧 | Table | 一覧できればよい |
| T3 | 生活歴・アレルギー歴一覧 | Table | 喫煙歴は禁煙いつからかまで必要、あとは一覧できればよい |
| T4 | 既往歴と治療内容 | 理想は既往歴が並んで、クリックすると展開されて関係薬剤ページ、医師カルテへのリンクだが |  |
| T5 | 検査結果 | Table | 異常値が無いか見るのが目的なので最新の日付つきで全部見れればよい、クリックで経時変化にとべればなおよい |
| T6 | 麻酔歴の確認 | ? | 麻酔記録をまるまる見たいのでなんとも |
| T7 | 麻酔リスクの判定 | TextInput | #でならべるが、フリースタイル |

## 4. データ（data nodes）

各ウィジェットが必要とするデータを、診療現場の言葉で具体化

### 4.1 ウィジェット × データ 対応表

| ウィジェット | 必要なデータ項目 | 期間 / 抽出条件 | 現 EHR での所在（テーブル・画面） |
| --- | --- | --- | --- |
| 患者情報一覧 | 年齢、性別、最新の身長、体重、BMI、身体測定の日付 | 最新のもの | 患者情報 |
| 手術申し込み内容一覧 | 診療科、診断病名、術式名、予定日、予定手術時間、予定体位 | 最新のもの | 手術申し込み |
| 生活歴・アレルギー歴一覧 | 喫煙歴（never,current,禁煙）、禁煙期間、飲酒頻度、飲酒量、アレルギーリスト | 最新のもの | 患者情報 |
| 既往歴と治療内容 | 既往歴（病名のリスト）、治療内容（内服薬、手術歴のリスト） | すべて | カルテ、時に紹介状 |
| 検査結果 | 検査されている項目すべて | 基本的には直近1か月で最新のもの | 血液検査、生理検査 |
| 麻酔歴の確認 | 麻酔記録 | 過去の麻酔記録のうち直近のもの | 麻酔記録システム |
| 麻酔リスクの判定 |  |  |  |

### 4.2 データに関する補足

- 患者を一意に決める情報（例：患者 ID）：患者ID
- 期間指定の基準日（例：診察日）：手術日
- 「あれば嬉しい」が必須ではないデータ：輸血オーダー

## 7. 既存 EHR の不満点 / 改善ポイント

このシナリオを現行 EHR で実施する際に、特に時間や認知負荷を取られている操作は？

- 不満点 1：閲覧ページが多く、閲覧ごとにクリックや、ページ切替のロスタイムが生じる
- 不満点 2：記入ページが強制アクティブで最前に表示され、閲覧するときに消して、記入するとき立ち上げ直しを繰り返さないといけない（これはKINGがカス）
- 不満点 3：部門システムに飛ばないといけないタスクがあり、それぞれ起動に時間がかかる
