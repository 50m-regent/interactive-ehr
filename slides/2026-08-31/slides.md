# 部品ごとの確認では誤りを見逃した

1. 個別に確認する方法

   SQLや表示部品が単独で動くかを確認した。

   質問と表示内容のずれを見逃した。

2. 対応をまとめて確認する方法

   質問、SQL、結果、表示の対応を確認した。

   誤りを含む763件をすべて見つけた。

<!-- _class: summary -->

# 今回の技術評価で分かったこと

1. SQLや画面を個別に見るだけでは、質問とのずれが残る
2. 質問から表示までをまとめて照合すると、誤りを見つけられる
3. 同じ内容をグラフと1枚の表で持つ場合、結果は同じだった
4. 安全性、使いやすさ、現行電子カルテとの利用比較は別研究で確かめる

<!-- _class: procedure -->

# 人を対象とする評価は別研究として計画する

1. 研究計画を定める

   研究目的、対象、取得情報、分析方法を整理する

2. 倫理審査と実施許可を得る

   同意、撤回、募集、データ管理の範囲を確認する

3. 許可後に実施する

   専門家確認済みの合成シナリオで画面を比較する

---

<!-- _class: summary accent-labels wide-labels -->

# 別研究で確認したいこと

| 確認内容 | 扱い |
| --- | --- |
| 診療タスク | 専門家が必要情報と完了条件を確認する |
| 合成シナリオ | 質問、正解、重大な見落としを固定する |
| 画面比較 | 回答の正しさ、操作、主観評価を測る |

<!-- _class: timeline -->

# 別研究を開始するまで

1. 研究目的と評価項目を整理 `計画`
2. 専門家がタスクと採点基準を確認 `仕様確定`
3. 倫理審査と実施許可を確認 `開始条件`
4. 許可された方法で募集と評価を実施 `許可後`

---
