# 質問から表示までをつなぐ

1. 診療時の質問
2. 必要な情報を整理
3. SQLでデータを取得
4. 用途に合う形で表示

質問と表示内容の対応を後から確認できる形で保存する

# 質問と表示内容が一致するか確かめた

画面、SQL、実行結果が単独で動いても、利用者の質問と表示内容がずれることがある。

| 比較の規模 | 内容 |
| --- | --- |
| 質問数 | 正解SQLを持つ934件 |
| 更新案の組数 | 正しい案と誤りを含む案の763組 |
| 比較条件 | 確認範囲が異なる4種類 |
| 実行回数 | 763組×2案×4種類、合計6,104回 |

---

<!-- _class: comparison -->

# 部品ごとの確認では誤りを見逃した

1. 個別に確認する方法

   SQLや表示部品が単独で動くかを確認した。

   質問と表示内容のずれを見逃した。

2. 対応をまとめて確認する方法

   質問、SQL、結果、表示の対応を確認した。

   誤りを含む763件をすべて見つけた。

---

<!-- _class: summary -->

# 今回の技術評価で分かったこと

1. SQLや画面を個別に見るだけでは、質問とのずれが残る
2. 質問から表示までをまとめて照合すると、誤りを見つけられる
3. 同じ内容をグラフと1枚の表で持つ場合、結果は同じだった
4. 安全性、使いやすさ、現行電子カルテとの利用比較はこれから確かめる

<!-- _class: comparison -->

# 次は医療従事者によるユーザー評価へ進む

1. 現在まで

   公開デモデータを使い、
   質問と表示内容が対応するか確かめた。

2. 今後

   専門家が確認したシナリオを使い、
   現行画面と提案画面を比較する。

---

<!-- _class: procedure -->

# ユーザー評価は3段階で進めたい

1. ヒアリング

   実際の確認手順と必要情報を整理する

2. シナリオ作成

   シナリオ、質問、正解、見落とせない情報を決める

3. 使用比較

   現行画面と提案画面で回答の正しさと操作を比べる

---

# ご協力をお願いしたいこと

| 進め方 | お願いしたいこと |

| 使い比べる | 二つの画面で回答し、情報と操作について意見をもらう |
