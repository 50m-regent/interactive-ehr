# CHI原稿の査読と改訂記録

2026年9月7日。日英の本文全体、図表、参考文献、評価コード、固定済みの集計を確認した。

私が査読者なら、改訂前は不採択を推す。改訂後も、現時点では採択を支持しにくい。既知の正解を持つ回帰テストとしての説明は改善したが、実際の生成UIに対する有効性と、既存の検査方法に対する研究上の差を示す証拠が足りない。文章の修正だけで採択圏に入ったとは判断しない。採択確率を数値化できる根拠もない。

次に優先するのは、検査器を固定したうえで実際に生成された更新を評価し、独立した正解判断と妥当な別解を含めて検査すること。医療者の作業改善を中心に主張するなら、その主張に対応する人対象評価も必要になる。人対象実験がすべてのCHI論文に必須という意味ではない。CHIは貢献の意義、新規性、妥当性、明瞭さを評価する。[CHI 2027 Papers公式案内](https://chi2027.acm.org/authors/papers/)

## 追加実験後の判断

全体査読の後、ユーザーの承認を受けて既存データによる追加実験を実施した。[追加評価の報告](../../../experiments/chi-additional-20260907/REPORT.md)に、条件、分母、結果、検証を記録した。層間検査は同じ列・型・結果を返すSQLの別解648件をすべて拒否し、SQL一致を除く判定は、結果を変えた476件のうち329件を受理した。元の100%検出と100%受理を一般的な意味の検証へ広げられないことが、実験でも確認された。

採択を支持しにくいという判断は変わらない。SQL一致を外すだけの修正は推さない。許容する別解と検出すべき結果変更を区別する契約を設計し、その設計に使わなかったケースと実際の生成更新で確かめることを優先する。以下の全体査読は追加実験前の記録であり、未評価と記した項目のうち、診断の再集計と限定したSQL変換は今回実施した。自然な生成誤り、独立した臨床判断、人への効果は未評価のままである。

## 採否に関わる懸念

| 査読上の懸念 | 確認できた事実 | 判断と必要な対応 |
|---|---|---|
| 正解判定と検査器が同じ目標を知っている | `oracle_candidate_valid` は選択した参照項目との一致を求める。層間検査も同じ契約を使い、正解SQLのチェックサムを照合する | 正解を知らない生成状態の意味的な誤りを検査できる証拠にはならない。独立した正解判断、同値な別解、期待値の入手方法を評価する |
| 比較条件の結果が構築方法に左右される | `_build_pair` は局所検査を通る不整合だけを採用する。グラフ検査と表形式検査は主要関数を共有する | 局所検査100%流出は採用条件の確認。二つの層間検査の一致から保存形式の効果は判断できない。正解との完全一致だけを使う条件や、検査項目を外した条件との比較が必要 |
| 自動修復の評価になっていない | `_repair_candidate` には注入した種類と妥当候補を渡す。該当種類が診断にあれば、データ成果物または表示部品全体をコピーする | 100%は参照情報を使う復元の結果。未知の原因を推定し、修正する能力は未評価。種類の正解と妥当な目標を渡さない別評価が必要 |
| 問題箇所を正確に特定したとは言えない | 注入した種類が報告の集合に含まれれば成功。余分な種類は減点せず、正確なノードや辺も採点しない | 指標を種類の報告率へ限定した。診断精度や位置の特定、人が修正に使えるかは別に測る |
| 生成UIと臨床業務への接続が未検証 | 正式評価で生成モデルやブラウザを使っていない。二つの診療シナリオは評価ケースでなく、専門家確認も未完了 | 生成誤りの分布、8分類の妥当性、複雑な画面での有効性は不明。動機の記述を厚くしても、この不足は埋まらない |
| 新規性の根拠が弱い | 既知の故障に対応する照合規則を与えている。中間表現、整合性検査、オラクルは先行研究にある | 故障モデルと評価資源が何を新たに調べられるようにするかを、既存手法との比較で示す必要がある |

評価コードの確認箇所は `src/interactive_ehr/evaluation/tracebench_ehr.py` の `oracle_candidate_valid`、`_build_pairs`、`_build_pair`、`_mutated_candidate`、`_build_contract`、`_evaluate_candidate`、`_repair_candidate`、`_local_issues`、`_artifact_issues`、`_graph_issues`、`_sidecar_issues`、`_semantic_query_issues`。これらの挙動を変えず、本文を合わせた。

## 数値が示す範囲

対象は自然に発生した763件のエラーではない。934件の回答可能ケースと134種類の質問テンプレートから構築した、763組の更新ペアである。同じテンプレートや元ケースを再利用する場合があり、6,104回は候補2種と条件4種を掛けた検査回数である。

| 項目 | 固定済みの結果 | 解釈 |
|---|---|---|
| 局所検査の流出 | 763/763 | 局所検査を通る候補を選んだ結果 |
| 成果物内検査の流出 | 367/763、48.10% | 情報源の記録、結果版、表示規則などの限定した検査で残った故障 |
| 二つの層間検査の流出 | それぞれ0/763 | 既知の目標と共有する検査関数による、定義済み故障の検出 |
| 妥当候補の受理 | 全条件763/763 | 参照情報から作った妥当候補への結果。意味が同じ別解の受理率は不明 |
| 成果物内検査の種類報告 | 387/763、50.72% | 拒否396件のうち9件は注入した種類を報告しなかった |

| 二つの層間検査の復元 | それぞれ763/763 | 注入情報と妥当な目標部品を渡した復元 |
| 候補の構築失敗 | 延べ3,420回 | 患者1,140、項目1,383、期間576、集約321。除外された固有の質問数や患者数ではない |

95%区間は質問テンプレート単位のブートストラップによる。テンプレートをまたぐ患者や変異規則の共有、自然な生成誤り、他施設への一般化の不確かさは含まない。検査時間はSQL実行、候補生成、復元、ブラウザ描画を含まない。

情報源の変異は、SQLの参照先を別の表へ変える操作ではなく、記録した表一覧の変更だった。表示方法の変異も、あらかじめ定めた表示規則への違反であり、臨床的に誤解を生む画面と判定したものではない。

## 投稿判断の前に揃える証拠

まず、参照情報を使う開発者向け回帰テストを主な貢献にするか、生成時の誤り検出や医療者支援まで主張するかを共著者と決める。後者を主張するなら、現行結果だけでは足りない。

技術評価では、検査器と分析方法を先に固定し、実際の生成更新と妥当な別解を集める。検査器の設計から独立した判断で正解を定め、正解SQLの一致だけを使う条件と、各検査を外した条件を比べる。復元を修復へ広げる評価では、注入した種類と妥当な目標成果物を渡さず、修正後の正しさと他の情報への影響を確かめる。

臨床の貢献を残す場合は、専門家にシナリオ、表示規則、重大な見落としの定義を確認してもらう。医療者の作業改善を主張する人対象評価は、倫理審査と実施許可の範囲を確認してから行う。今回、新たな実験や人対象のデータ収集は実施していない。
